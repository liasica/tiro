# Tiro

把飞书妙记自动整理成会议纪要。

Tiro 定时检查授权用户名下的新妙记，取回逐字稿，交给 OpenAI 格式的模型接口按模板写成纪要，在该用户的飞书云空间创建文档，再由机器人私聊把链接发给本人。

成员可以在后台或机器人私聊里提问，例如「帮我找找 11.10-11.15 的待办事项」，Agent 检索妙记与纪要作答，每条结论附引用来源，可跳到纪要、妙记或妙记里的具体时间点。每个对话的问答写进提问人云空间里的一个多维表格。

## 运行

需要 Go 1.27、Node 26 与 pnpm 12。

```bash
make all
```

```bash
./bin/tiro
```

启动后打开 <http://localhost:8476>。首次打开进入初始化向导：

1. 用飞书扫码创建应用
2. 用飞书扫码授权，第一个授权的人成为管理员
3. 填写模型接口的地址、模型名与密钥

完成后进入后台。之后新生成的妙记会在几分钟内出现在「纪要」列表里并自动生成文档。

## 启动参数

| 参数 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `-addr` | `TIRO_ADDR` | `:8476` | 后台的监听地址 |
| `-data` | `TIRO_DATA_DIR` | `data` | 数据目录，存放 SQLite 数据库 |

其余配置都在后台的「设置」页里：模型接口、检查间隔、云空间文件夹名、逐字稿最短字数、术语表、纪要提示词。

数据目录里的 `tiro.db` 保存飞书应用凭据、用户令牌与模型接口密钥，备份与迁移时整目录带走。

## 机器人对话与对话记录

在飞书开发者后台完成以下配置，然后创建版本并发布：

1. 「事件与回调」的订阅方式选择「使用长连接接收事件」，tiro 运行时才能保存；添加事件「接收消息」（`im.message.receive_v1`）
2. 「权限管理」开通「读取用户发给机器人的单聊消息」（`im:message.p2p_msg:readonly`）与「查看、评论、编辑和管理多维表格」（`bitable:app`）

开通 `bitable:app` 之前已授权的成员需要重新扫码登录一次。私聊机器人直接提问即可，发送「新对话」或「结束」结束当前对话。

对话模型在「设置 → 对话模型」按接口添加：填写接口地址与密钥（例如 OpenAI 官方的 `https://api.openai.com/v1`），获取模型列表后勾选要用的模型并选择默认模型；不添加时沿用纪要的模型接口。接口格式可选 Chat Completions 或 Responses，OpenAI 官方接口用 Responses。模型需要支持流式输出与工具调用。

## 后台

- **纪要**：每条妙记的处理状态、生成的纪要预览、飞书文档链接与历次模型调用的 token 用量；管理员可以粘贴妙记链接手动添加，也可以重新生成
- **对话**：与 Agent 问答，可限定时间段或手动选择妙记，可切换模型；回答附引用来源，对话可以结束，每个对话对应一个多维表格
- **成员**：已授权的成员、授权状态，以及是否为其自动生成纪要
- **设置**：模型接口、对话模型、运行参数、术语表、纪要提示词、机器人长连接状态，以及机器人菜单要填写的链接

其他成员打开后台扫码登录即完成授权，此后名下的新妙记自动生成纪要。成员只能查看自己的纪要；设置、成员管理、手动添加与重新生成只有管理员可用，管理员可以在「纪要」页切换查看全部成员的记录。

## 机器人菜单

给机器人加一个菜单，成员在机器人私聊里点击即可打开自己的纪要列表，在飞书内打开时自动登录。按「设置 → 机器人菜单」给出的链接，在飞书开发者后台完成三步：

1. 「安全设置」的重定向 URL 中添加重定向 URL
2. 「机器人」页开启机器人自定义菜单，添加菜单项，响应动作选「跳转至指定链接」，填写菜单链接；桌面端可以填写桌面端链接，在聊天侧边栏打开
3. 创建版本并发布

后台需要能从成员的手机与电脑访问。经反向代理部署时，代理需要转发原始的 `Host` 与 `X-Forwarded-Proto`，重定向 URL 才能与后台的实际地址一致。
